## 1. Architecture Overview: Existing Canonical & Operational Layers

1. **Universal Ingestion Canonical Contract (`srv/canonicalData.js` + `credit.CanonicalRecords` in `db/schema.cds:153-167`)**:

   - `credit.Customers` (`db/schema.cds:3-15`), `credit.OpenItems` (`db/schema.cds:17-25`), and `credit.Payments` (`db/schema.cds:27-35`).
   - Consumed directly by `srv/creditService.js`, `srv/portfolioDataProvider.js`, `srv/monitoringService.js`, and `srv/rules.js`.
3. **3-Layer FIN-FSCM Canonical Repository (`db/schema.cds:302-471` + `srv/canonicalSchemaMetadata.js`)**:

## 4. Unrepresentable Categories & Items ("Needs Approval" — Proposed Only, Not Implemented)

*(Verify in SE11/SE16N for the target SAP release.)*

In accordance with architectural boundaries, **open sales orders, deliveries, and unposted billing documents are never mapped to `INVOICE`**, and **unreferenced credit memos (`DG`) or unallocated payments on account (`DZ` in `BSID`) are never silently netted or falsified as positive invoices**. The following categories cannot be represented in `srv/canonicalData.js` or `srv/rules.js` without schema/rule changes and therefore require explicit product-owner approval before implementation:

1. **Open Outbound Deliveries (`LIKP`/`LIPS` / `UKM_ITEM.COMM_TYP = 'OPEN_DELIVERY'` — *Verify in SE11/SE16N for the target SAP release.*)**:
   - *Current Gap*: `srv/canonicalData.js:1-8` has no `DELIVERY` entity type, and `srv/rules.js:24` (`EXPOSURE_TYPES = new Set(['invoice', 'salesorder'])`) ignores `type = 'Delivery'` on `credit.OpenItems`.
   - *Proposal (Needs Approval)*: Add `DELIVERY` to `ENTITY_TYPES` in `srv/canonicalData.js` and add `'delivery'` to `EXPOSURE_TYPES` in `srv/rules.js` (or route portfolio calculations through `credit.CG_CREDIT_EXPOSURE_ITEM` where `OPEN_DELIVERY` is already defined in `srv/canonicalSchemaMetadata.js:14`).
2. **Unposted Billing Documents (`VBRK`/`VBRP` with `RFBSK <> 'C'` / `UKM_ITEM.COMM_TYP = 'OPEN_BILLING'` — *Verify in SE11/SE16N for the target SAP release.*)**:
   - *Current Gap*: Billing documents not yet transferred to FI-AR are not in `BSID` and must not be conflated with posted FI-AR `INVOICE` records.

   - *Proposal (Needs Approval)*: Add a `creditBlocked : Boolean` field to `credit.Customers` (or read `credit.CG_BP_CREDIT_SEGMENT.credit_blocked`) and emit a dedicated `CREDIT_BLOCKED` flag in `srv/rules.js`.
